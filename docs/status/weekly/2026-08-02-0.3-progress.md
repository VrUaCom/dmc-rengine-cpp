## Generic container architecture

The generic architecture is green and no longer a blocker:

```text
bytes
  → IContainerParser
  → ContainerDocument / diagnostics
  → ContainerExpander
  → child ResourcePayloads
  → ResourceGraph contains edges
```

The public synthetic `SLTC` format tests slot identity, empty slots, fallback names, truncation, out-of-range entries, overlap, child classification, and graph integration.

This does not claim PAC/PNST/AFS/NBZ compatibility.

## HITS$ migration

The narrow confirmed record scanner is committed and specified:

- `HITS$` magic;
- marker `0x18060001`;
- 56-byte record;
- thirteen raw float values;
- synthetic valid/truncated/no-record tests.

The implementation deliberately does not assign semantic names to the floats or invent a complete file header.

A Binary Inspector adapter source/test is drafted and tracked separately until build integration, cross-platform validation, and sample-hash Evidence are complete.

## Architecture assessment

Healthy:

- one resource API;
- no second resolver;
- no direct original-file writes;
- strict Evidence import/export;
- unknown structures remain visible;
- game-specific metadata remains outside generic parsers;
- synthetic fixtures remain legally clean.

Main risk:

- real PAC/PNST migration could tempt schema guessing. No production parser should be accepted without exact sample identity, field/slot evidence, malformed-input tests, and explicit unsupported regions.
