# DMC3 gates 0–48: what each one showed, and where it lives in Rengine

2026-10-29. Target `dmc3.exe` SHA-256
`e454272ed0fb0247fcbcf300e5d55d7a3e96d50b89b9ffaff81bb978dcbdd082`.

The gates are proof-gated steps of two lines of work. A "device `PASS`" below
is one the later packages record; the archive holds no device reports of its
own.

- **Gates 0–30**: the Android ARM64 port probes. They built Rengine's own
  recovered C++ (and a few narrow probes) on a Samsung phone through Termux,
  against the user's own game files.
- **Gates 31–48**: the static reverse of the light path, from the LIG2 file to
  the shader constants.

Gates 0–43 come from the user's archive
`DMC3_Rengine_Reverse_Archive_Gates01-43_2026-10-28.zip` (48 packages of
scripts, tests and manifests; no game data). It is not committed. Gates 44–48
were worked out in the DMC Native Reader (`NR-Luna-v73`,
`docs/research/dmc3-gates-archive-v124.md`).

The archive's checks were Python scripts. Every gate fact that can be read off
the executable is now a C++ check in `tools/reverse/dmc3_gates.cpp`. It uses
Rengine's own PE reader, x86 length decoder, code graph (`.pdata` walk with
switch-table recovery) and RTTI scanner. Its last run on the canonical image
is `data/reverse/dmc3-gates-20261029.json`: **118 of 118 checks pass**.

```sh
cmake -B build -DDMC_RENGINE_BUILD_REVERSE_TOOLS=ON && cmake --build build --target dmc3-gates
build/dmc3-gates /path/to/dmc3.exe --json report.json   # refuses any other SHA-256
build/dmc3-gates --self-test                            # no game data needed (CTest)
```
