# DMC3 — аудит неповноти внутрішнього дерева

Дата: 2026-09-15. Гілка: Ада-Астра.
EXE SHA-256: `e454272ed0fb0247fcbcf300e5d55d7a3e96d50b89b9ffaff81bb978dcbdd082`.

## Висновок: дерево НЕ виявлене до кінця

Попередній звіт про 20 доменів — карта організації дослідження, а не доказ,
що всі підсистеми, класи, глобальні об'єкти та зв'язки вже знайдені.
407 RTTI-типів, 438 ребер наслідування і 915 vtable anchors описують лише
структуру, видиму за обраними метаданими. Класи без RTTI, нетипізовані
менеджери, callback-таблиці та зв'язки володіння не мають закритого переліку.

Новий аудит зіставив незалежні джерела коренів із попереднім bounded CFG.
Виявлено **7450 унікальних адрес-коренів, відсутніх у цьому CFG**, уже
підтверджених CRT-таблицями, першими записами vtable або unwind-обробниками.
Це доводить неповноту інтегрованого обходу, але не означає 7450 нових класів,
незалежних функцій або адрес, невідомих усім попереднім дослідженням.

## Виміряні пропуски

| Перевірений аспект | Наявні структурні дані | Відсутнє в CFG від 14 вересня |
|---|---:|---:|
| Ненульові `_initterm` targets | 6984 унікальні адреси | **6930** |
| Ненульові `_initterm_e` targets | 3 | 0 |
| Перші записи vtable | 915 записів / 894 унікальні цілі | **522 записи / 519 унікальних цілей** |
| Exception-handler targets | 2210 записів / 4 унікальні цілі | **5 записів / 1 унікальна ціль** |
| RTTI-типи без спостережуваної бази | **57** | зв'язки ownership/служб не визначаються цим числом |

Сума унікальних непокритих коренів після дедуплікації — 7450. Жодна з цих
адрес не є серединою інструкції поточного CFG. Це нові точки входу для
розширення обходу, а не підстава автоматично називати всі їхні функції.

### Чому попередній обхід їх пропустив

Його початкові корені були PE entry та runtime-range starts, за винятком
п'яти підтверджених таблиць даних. Потім він переходив за прямими гілками
і шістьма вручну перевіреними switch-таблицями. Обхід не розгортав масив
CRT-конструкторів, не засівав усі vtable targets і не додавав усі
exception-handler entrypoints. Це задокументована межа алгоритму, тепер
виміряна за адресами. Відсутність помилок декодування на 611752 інструкціях
не є доказом повноти коду чи архітектури.

Приклади:

- CRT slot `0x14034F818` → `0x1400010F0`, slot `0x14034F828` → `0x140001000`.
  Обидві адреси відсутні в попередньому CFG.
- `FullMotionVideo@DMC3`, vtable `0x14035D380` → `0x14002AB80`.
- `CActor`, vtable `0x1404C5DA0` → `0x14004C8BC`.
- П'ять unwind-записів посилаються на `0x140346C08`: це jump thunk через
  IAT `0x14034F3E0`, який названий `VCRUNTIME140.dll!__C_specific_handler`.
  Наявність імпорту раніше не означала включення цього thunk у CFG.

## Ще не визначені межі vtable

Додатковий скан починається з 915 підтверджених anchors та читає послідовні
64-бітні вказівники у виконувані секції. Він зупиняється перед наступним
locator slot, на невиконуваному вказівнику або після 256 записів.

Отримано **13882 кандидатні записи**, 3307 унікальних адрес; 1418 унікальних
цілей відсутні в CFG. Це **SEMANTIC_CANDIDATE**, не доведена кількість
віртуальних методів: сусідня pointer-таблиця теж може містити адреси коду.
Ці числа не додаються до 7450 як незалежні нові корені.

Три послідовності досягли обмеження 256:
`0x1404C6A18`, `0x1404C75E0`, `0x1404C7EA0`.
Їхні кінці не встановлені. Решта stop conditions також не доводять
семантичні межі C++ vtable. Потрібні constructors, destructors, адреси
записів vptr, slot consumers і adjustor thunks.

## Які невідомості залишаються саме в структурі

| Область | Що ще не доведено | Умова закриття |
|---|---|---|
| Корені виконання | включення всіх відомих CRT/vtable/handler targets | обхід із provenance кожного кореня та повторна звірка |
| Типи | повнота класів без RTTI, зовнішніх баз і нетипізованих об'єктів | додаткові constructor/vptr/layout докази; явний залишок невідомих |
| Vtable | довжини, slot ABI, shared methods, thunks | межі та призначення кожного слоту підтверджені consumers |
| Глобальні об'єкти | initializer → instance → destructor → users | перевірені адресні зв'язки й життєвий цикл |
| Менеджери | хто створює, володіє і видаляє кожен екземпляр | ownership-граф; аргумент виклику сам по собі недостатній |
| Головний цикл | порядок update, draw, async work, переходів сцен | call/dispatch paths разом з умовами виконання |
| Реєстри | усі factories, callbacks, switch tables, indirect targets | межі, селектори, default paths та невирішені цілі |
| Shutdown | порядок cleanup між scenes, ресурсами, FMOD, Steam, CRT | підтверджені destructor/registration/call paths |
| Повнота доменів | чи є додаткові підсистеми поза 20 рубриками | кілька незалежних проходів без некласифікованих структурних знахідок |

57 RTTI-коренів можуть бути цілком законними інтерфейсами: наприклад
`IUnknown`, `IActor`, `ISceneFactory`, `CSceneMgr`, `IDraw`, `CGameLoader`.
Не можна трактувати їх як 57 загублених батьків або 57 нових підсистем.
Перелік збережено для адресного, а не суто іменного аналізу.

**Статус аспекту: OPEN / NOT EXHAUSTIVE.** Відсоток повноти дерева не
обчислюється: загальна кількість його вузлів та зв'язків ще невідома.

## Артефакти і перевірка

`data/reverse/tree-completeness-20260915/` містить повні адресні переліки
пропущених/покритих CRT targets, перших vtable entries, кандидатних slots,
handler targets, RTTI-коренів, summary та verification receipt.

```sh
python scripts/reverse/audit_runtime_tree_coverage.py /path/to/dmc3.exe \
  data/reverse/runtime-tree-20260913 data/reverse/exe-cfg-20260914 \
  data/reverse/exe-structure-20260915 /tmp/tree-audit
```

Python standard library. Canonical EXE hash перевіряється до створення
виходу. Перші vtable entries повторно прочитані з EXE; handler RVAs
прочитані після вирівняного масиву unwind codes. Усі targets цих джерел
перевірено на належність до виконуваних секцій. Зіставлено 10112
підтверджених metadata-root records, перераховано суму унікальних пропусків.
Скан не виконує гру і не заявляє перевірки runtime-поведінки.

Цей аудит доповнює `dmc3-main-structure-2026-09-15.md` та уточнює межі
`dmc3-cfg-decoding-2026-09-14.md`. Він не відкидає підтверджені адреси
попередніх проходів; він показує, яких інтеграційних зв'язків бракує.
