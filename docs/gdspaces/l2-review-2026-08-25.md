## What remains confirmed from the previous Layer-2 audit

### Candidate construction and provider order

- lookup starts from the request basename;
- six prefixes are attempted in recovered order: `GDataX360.afs/`, `GData.afs/`, `Video/`, `afs/sound/`, `SAVEDATA/`, empty;
- archive attempts complete before physical attempts;
- archive normalization uses `0x0E`;
- physical normalization uses `0x0C`;
- the candidate attempt remains the outer precedence authority.

### Archive provider

- the original ZIP/NBZ backend owns a normalized sorted lookup representation;
- archive lookup uses the recovered `0x0E` qsort/bsearch path;
- `.index` files are not runtime authority;
- GDSpaces preserves comparator-equal distinct identities as explicit ambiguity rather than inventing an original winner.

### Volume bootstrap

- numbered `DMC3-%d.nbz` discovery is contiguous and first-gap bounded;
- physical mount is registered first;
- numbered archives are prepended, producing highest-contiguous-volume-to-zero lookup precedence;
- zero-volume bootstrap reaches the physical phase directly.

### Resolver ownership and fail-closed policy

- resolver indexes are derived from the exact currently mounted `ISource` enumeration rather than caller-owned stale index pointers;
- source mismatch / invalid resource / C-string-incompatible path / empty normalized key invalidate the source configuration;
- embedded-NUL requests fail before provider probing;
- archive/physical source-binding aliasing and duplicate archive volume/source bindings are rejected.

## New 2026-08-25 correction: physical provider

The previous blocker said the exact post-`0x0C` final physical open/comparison behavior was not directly recovered. That statement is now obsolete.

Direct reverse of the canonical executable establishes:

- type-0 mount registration at `0x140326D20` with normalization flags `0x0C`;
- physical resolution at `0x140327430`;
- bounded root join at `0x1403272C0`;
- existence check at `0x140327720` through `FindFirstFileA` / `FindClose`;
- final open at `0x140327800` through `CreateFileA(path, GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, 0, NULL)`;
- `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND` are normal open misses;
- `ERROR_NO_MORE_FILES`, `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND` are normal existence-check misses;
- other errors are retried;
- no additional game-side case-folding stage was found after `0x0C` before the Win32 path APIs.

The implementation consequence is deliberately conservative: knowing the original direct-open contract does **not** make the existing source-enumeration/index implementation mechanically identical to it.
