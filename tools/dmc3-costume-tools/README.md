# dmc3-costume-tools

Інструменти для одягу з фізикою в DMC3 (Special Edition, PC). Усе тут звірено
з канонічним `dmc3.exe`:

```
SHA-256 e454272ed0fb0247fcbcf300e5d55d7a3e96d50b89b9ffaff81bb978dcbdd082
```

Набір самостійний: лише Python 3 (плюс `coat_constraints.s` для патча), без
Native Reader. Жодних файлів гри тут немає. Інструменти читають ваші файли й
пишуть результат туди, куди ви скажете.

```sh
pip install -r requirements.txt       # numpy scipy pillow capstone unicorn
```

## Що є

### Утиліти для файлів

| Файл | Що робить |
| --- | --- |
| `pactool.py` | PAC: список слотів з типами, розпакування, заміна й додавання слотів, збирання |
| `ptxtool.py` | Текстури PTX (див. нижче) |
| `modtool.py` | Моделі MOD (див. нижче) |
| `clttool.py` | Тканина CLT: показати блоки, змінити параметри |
| `shwtool.py` | Тіні SHW: показати, перебудувати слоти 8 і 14 з поточних MOD |
| `pacheck.py` | Перевіряє PAC на ліміти EXE (див. нижче) |
| `dxt.py` | Кодек DXT1/DXT5 і контейнер PTX, бібліотека для інших скриптів |

`ptxtool.py` уміє:
- показати список текстур разом з проблемами (дескриптор, mip-рівні);
- експортувати текстури в PNG;
- замінити текстуру з PNG;
- додати нову текстуру;
- виправити дескриптори й mip-ланцюжки (`fix`).

`modtool.py` уміє:
- `info` — об'єкти, меші, текстури, скін, скелет;
- `layout` — карта байтів;
- `obj` — експорт в OBJ + MTL + PNG для Blender;
- `render` — PNG-прев'ю з текстурою;
- `roundtrip` — перевірка «читання → запис».

`pacheck.py` перевіряє скін, SHW, CLT (`ClothNum`), `CCNS`, ліміти вузлів і
наявність слоту 14.

### Одяг і патч

| Файл | Що робить |
| --- | --- |
| `fixmod.py` | Ремонт модового player PAC (див. нижче) |
| `modwriter.py` | Читання й запис MOD у ретейл-розкладці (див. нижче) |
| `costume.py` | Робить з тіла одяг з фізикою: спідниця, стрічка, рукави (pl011) |
| `coat_patch.py` + `coat_constraints.s` | Патч `dmc3.exe` для даних одягу (див. нижче) |
| `verify_patch.py` | Емулює справжній код гри (unicorn) і перевіряє патч разом з PAC |
| `exe/` | Читання EXE: дизасемблер, пошук викликів і полів, межі функцій, RTTI |

`fixmod.py` ремонтує модовий player PAC так:
- канонічні дескриптори PTX і повні mip-ланцюжки;
- власні тіні моделі (SHW, слот 8);
- слот 14, якого бракує.

`modwriter.py` читає й пише MOD у ретейл-розкладці. Дев'ять ретейл-MOD
відтворюються байт-у-байт.

`coat_patch.py` робить таке:
- корінь плаща можна вибрати в самому файлі плаща;
- вузли плаща можна прив'язати до кісток тіла;
- капсули зіткнень можна задати для кожного костюма окремо.

## Утиліти: приклади

```sh
# PAC
python3 pactool.py list    pl000.pac                    # слоти з типами (PTX, MOD, SHW, CLT, CCNS, PAC...)
python3 pactool.py extract pl000.pac pl000_slots        # slot_00.ptx, slot_01.mod, ...
python3 pactool.py replace pl000.pac 12 my_coat.mod -o out.pac
python3 pactool.py pack    pl000_slots -o pl000_new.pac # ретейл-PAC збираються байт-у-байт

# Текстури (player слот 0, stage слот 1; DXT1 і DXT5)
python3 ptxtool.py list    pl011.pac                    # розміри, формат, mip, проблеми дескриптора
python3 ptxtool.py export  pl011.pac textures/          # PNG (--mips: усі рівні)
python3 ptxtool.py replace pl011.pac 2 my_skin.png -o out.pac     # новий PNG з повним mip-ланцюжком
python3 ptxtool.py add     pl011.pac extra.png -o out.pac
python3 ptxtool.py fix     pl011.pac -o out.pac         # канонічні дескриптори, повні mip-ланцюжки

# Моделі
python3 modtool.py info      pl000.pac 12               # плащ Данте: об'єкти, меші, текстури, кістки
python3 modtool.py obj       pl011.pac 1 body.obj       # + body.mtl + body_tex*.png для Blender
python3 modtool.py render    pl000.pac 1 dante.png --yaw 180
python3 modtool.py layout    pl000.pac 1                # де що лежить у файлі
python3 modtool.py roundtrip pl000.pac 1                # read -> write байт-у-байт

# Тканина і тіні
python3 clttool.py show pl011_costume.pac
python3 clttool.py set  pl011_costume.pac Stiffness 0.45 -o out.pac
python3 clttool.py set  pl011_costume.pac Gravity 0 -0.02 0 -o out.pac
python3 shwtool.py show    pl000.pac
python3 shwtool.py rebuild my_mod.pac -o out.pac        # тіні під поточні моделі (+ слот 14, якщо бракує)

# Перевірка
python3 pacheck.py my_mod.pac                           # --vergil для pl001
```

Що перевірено:
- **Кодек:** DXT5 декодує піксель-у-піксель так само, як перевірений кодек
  `fixmod`. DXT1 і DXT5 перевірено на ретейл-текстурах pl000, pl001, em028,
  st000 і st001.
- **Дескриптори:** 49 ретейл-текстур проходять канонічну перевірку. Вона
  допускає обидва варіанти пари aux (`+0x3C`/`+0x40`) і вторинних розмірів
  (`+0x44`).
- **Незмінні файли:** бандли PTX, PAC і MOD, яких інструменти не змінювали,
  відтворюються байт-у-байт.

## Повний шлях (pl011)

```sh
python3 fixmod.py  pl011.pac pl000.pac pl011_fixed.pac
python3 costume.py pl011_fixed.pac pl000.pac pl011_costume.pac
python3 coat_patch.py dmc3.exe dmc3_coat.exe
python3 pacheck.py pl011_costume.pac
python3 verify_patch.py dmc3_coat.exe pl011_costume.pac pl000.pac
```

`pl000.pac` — ретейл-Данте. З нього беруться заголовки SHW і плаща, а також
шаблон заголовка DDS.

Результати відтворюються байт-у-байт (SHA-256):

| Файл | SHA-256 |
| --- | --- |
| `pl011_fixed.pac` | `de580ff960152640cf51f0b86e1c6e1f369a309c1419863db8cc6309ab435596` |
| `pl011_costume.pac` | `f4fcaa75334541bb93ff85cebf0de7d4b16a92d77e109afef5e99c1fd95755cb` |
| `dmc3_coat.exe` | `bfa4f84d9b6879aef48a95e57a9bc8c38f706e186f5af379564bb494549311bd` |

`coat_patch.py --verify-asm coat_constraints.s` перезбирає асемблерну частину
(потрібні `as`, `ld` і `objcopy` з binutils) і звіряє її з байтами в скрипті.

## Як гра рахує плащ (підтверджено в EXE)

### Слоти player PAC

| Слот | Вміст |
| --- | --- |
| 0 | PTX, спільний для тіла й плаща |
| 1 | MOD тіла |
| 8 | SHW тіла |
| 12 | MOD плаща |
| 13 | CLT, фізика тканини |
| 14 | SHW плаща |
| 15 | `CCNS`, лише з патчем |

- Геттер слотів — `0x1401B82C0`.
- Слот 14 обов'язковий. Ініціалізація гравця (`0x140215206`) передає його в
  об'єкт тіні без перевірки на null.

### Корінь плаща

- CPlDante ставить корінь плаща на світову матрицю кістки 3. Місця в коді:
  `0x1402120C4`, `0x140218EFD`, `0x140218F67`.
- Вказівники на кістки тіла: `player+0x1880 + 8·j`, 96 кісток.

### Вузли плаща

- Таблиця вузлів плаща: `player+0xA0D0`. Конструктор `0x1401DE820` виділяє
  рівно **39** вузлів.
- Прив'язка `0x14030F850` ставить для кожного вузла `+0x110` (світ), `+0x108`
  (локальна), `+0xF0` (батько) і `+0x100 = 0` (обмеження).
- Оновлення скелета `0x14030E680`: вузол, у якого увімкнене обмеження на
  `+0x100`, рахує свій світ через обмеження, решта — як локальна × батько.

### Обмеження `CCnsMatrix`

- vtable `0x1404CC1F8`, конструктор `0x1400F7AC0`, 0xC0 байт.
- Поля: `+0x20` увімкнено, `+0x28` режим, `+0x30` вказівник на світ
  кістки-господаря, `+0x80` зсув.
- Режим 1 (`0x1402CBBE0`): світ = зсув × господар (row-vector).
- Так зроблені рукави й сукня Невана (CEm028, `0x140130480`).

### Тканина

- Ланцюги тканини в Данте починаються на `+0xA210`, а на `+0xA300` вже йде
  таблиця кісток. Тому в Данте лише **один** блок CLT (`ClothNum 1`).
- У Вергілія два блоки (`+0xA230` .. `+0xA410`).
- Перевірки на `ClothNum` немає. `ClothNum 2` у Данте затирає пам'ять.
- Зіткнення має лише перший блок.

### Капсули

- 6 форм по 0x50 байт у `player+0xB630`: A на `+0x10`, B на `+0x20`, радіус
  на `+0x30`.
- Кістки: 3, 2, 15, 16, 19, 20 (таблиця `0x14058B380`).
- Гра копіює форми з `.rdata 0x14058B260` під час завантаження. Сетер
  `0x1402CA2F0` лише зберігає вказівник, а крок симуляції `0x1402C97F0`
  читає форми щокадру.

### Два шляхи налаштування плаща в CPlDante

- Байт костюма `+0x3E9E` = 1 або 4: шлях `0x14021526F`.
- Інакше: шлях `0x140214F74`.
- Обидва закінчуються `lea rdx,[r14+0x1880]` перед сетером капсул:
  `0x140215373` і `0x1402151C3`.

## Патч (`coat_patch.py`)

1. **Корінь плаща.** Три місця з кісткою 3 викликають маленькі підпрограми в
   `int3`-набивці (`0x140346CF2`, `0x1403455D5`). Вони беруть кістку 3 +
   `byte [player+0x76BA]`.
   - `player+0x76BA` — це копія байта `+0x13` заголовка MOD плаща.
   - Об'єкт плаща лежить на `+0x7540` (клас CDraw), його менеджер на
     `+0x80`, копія байта на `+0xFA` (`0x1402F960E`).
   - Ретейл-плащі мають там 0, тож лишаються на грудях.
2. **Нова секція `.dmcx`** (VA `0x140DAC000`, RWX) з `coat_constraints.s`.
   - Її викликають обидва шляхи налаштування плаща.
   - Вона читає слот 15 (`CCNS`). Ретейл-гра цей слот не читає, тож PAC без
     нього поводяться як раніше.
   - Вона ставить обмеження режиму 1 на перелічені вузли й записує форми
     капсул.
   - Пул обмежень: 4 гравці × 16.
3. **Підпис і контрольна сума.** Підпис Authenticode прибрано (після зміни
   він однаково недійсний). Контрольну суму PE перераховано.

Скрипт працює лише з канонічним EXE і перед зміною звіряє кожен байт.

### Слот 15, `CCNS`

```
+0x00 'CCNS'   +0x04 версія 1   +0x08 кількість вузлів (<=16)   +0x0C кількість капсул (<=6)
+0x10 вузли, по 0x50: u32 вузол плаща (<39), u32 кістка тіла (<96), u64 0,
      f32[16] зсув (row-vector)
далі капсули, по 0x40: u32 індекс форми (0..5), 12 байт 0,
      f32[4] A, f32[4] B, f32[4] радіус (у просторі кістки)
```

## Як влаштований костюм (`costume.py`)

- **Корінь:** таз (заголовок `+0x13 = 11`, тобто кістка 3 + 11 = 14).
- **Спідниця:** 8 ланцюжків (вузол-корінь + 2 ланки). Усі фізичні.
- **Рукави:** по три прив'язки на кістки 6/7/8 і 10/11/12 з одиничним
  зсувом, у позиціях спокою кісток. Власні ваги рукава на цих кістках
  переносяться один в один. Ланцюг з 3 ланок від ліктя несе нижню половину
  дзвону.
- **Капсули** під фігуру:
  - торс (кістка 3): від (0, 20, 1) до (0, −12, 1), r 11;
  - таз: r 12;
  - ноги: r 9.
- **Тіні:** SHW тіла без одягу, SHW одягу з оболонками по ланцюжках.
- **Разом:** 37 вузлів, 22 кістки тканини, 6 обмежень, 6 капсул.

Якщо ви робите власний костюм:
- змініть вибір трикутників (спідниця — за блоком UV, рукави — за кістками
  й кольором текстури);
- змініть кількість ланцюжків, кістки прив'язок і форми капсул
  (`CAPSULES`);
- тримайтеся лімітів: 39 вузлів, 1 блок CLT, 16 прив'язок, 6 капсул.

`pacheck.py` ловить вихід за ці ліміти.

## Читання EXE (`exe/`)

```sh
python3 exe/xdis.py  dmc3.exe 0x1402120A7              # дизасемблер (до кінця функції з .pdata)
python3 exe/xref.py  dmc3.exe 0x1402F9570              # хто викликає / де вказівник
python3 exe/xref.py  dmc3.exe 0 --disp 0xA0D0          # хто чіпає поле +0xA0D0
python3 exe/pdata.py dmc3.exe 0x140215373              # межі функції
python3 exe/rtti.py  dmc3.exe 0x1404DFA38              # клас і номер слота vtable
```
